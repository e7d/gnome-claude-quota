# Translations — design

**Date:** 2026-08-13
**Status:** designed

## Problem

Every string the extension shows is an English literal in the source. There are about twenty-five of
them, spread across five modules, and three of those modules are unit-tested under `node --test`,
where the shell's translation API does not exist.

That last point is what makes this more than a string sweep. The GNOME translation entry point is
`resource:///org/gnome/shell/extensions/extension.js`, importable only inside the shell. Reaching for
it directly from `lib/format.js` would make the module unimportable by the test runner and break the
rule the whole tree is built on: `lib/` runs in both places, `lib/usage.js` is the single deliberate
exception.

The second complication is French grammar, which the string inventory does not reveal until you try
to translate it. `captionLine` builds `4h 08m left` by concatenating a duration with the word `left`.
French agrees the participle with the leading unit — `4 j 0 h restants` (jours, masculine), `4 h 08
restantes` (heures, feminine), `1 min restante` (singular) — so `left` cannot exist as a msgid of its
own. No amount of catalog work fixes a sentence assembled from fragments; the code has to change.

## Scope

Ship the translation machinery and one catalog: French. Later languages are catalog files and
nothing else — that is the test of whether this design is right.

Out of scope: `metadata.json` `name` and `description` (the shell does not translate them), the
status-endpoint error strings (recorded to `attempts.jsonl`, never rendered), and any French e2e
assertion suite.

## What is already established

- `xgettext`, `msgmerge` and `msgfmt` are all on this workstation.
- GNOME 45+ constructs `Extension` with `initTranslations()` already applied when `metadata.json`
  carries `gettext-domain`, exposing `this.gettext`, `this.ngettext` and `this.pgettext`. This is
  read from the platform docs and **must be confirmed against a running shell** before the design is
  trusted — the tree's standing rule about shell APIs not behaving as their names suggest applies
  here as much as anywhere.
- `lib/format.js` already takes a `locale` argument derived from `LC_TIME`/`LANG` by `timeLocale()`,
  used for `Intl.DateTimeFormat`. Message language comes from `LC_MESSAGES`, which is a different
  variable, and they are allowed to disagree.
- Nothing pins `LC_ALL` anywhere. `npm test` pins only `TZ`, and the nested shell inherits the host
  environment. A French host therefore already renders the e2e tiles in French dates — a latent
  determinism bug this work has to fix regardless of translations.
- `relativeDuration` is exported and directly tested but has exactly one consumer, `captionLine`.
  Changing its contract costs four assertions.

## Design

### The shim

`lib/i18n.js` is a pure module holding a translator that defaults to identity:

```js
let translator = null;

export function setTranslator({gettext, ngettext, pgettext}) { … }
export function resetTranslator() { translator = null; }

export function _(msgid) { … }
export function n_(msgid, plural, count) { … }
export function p_(context, msgid) { … }
export function N_(msgid) { return msgid; }
export function format(pattern, values) { … }
```

`extension.js` installs the real translator in `enable()` and calls `resetTranslator()` in
`disable()`. Under `node --test` no translator is ever installed, so every module returns its English
msgid and all existing assertions stand unchanged. That is the point of the default, not a
convenience: a test suite that had to be re-baselined into a second language would double the cost of
every future string change.

`format(pattern, values)` substitutes `{name}` placeholders and leaves unknown ones untouched. Named
placeholders rather than `%s` because `{hours} h {minutes}` tells a translator what they are holding
and `%s %s` does not.

`N_()` is a no-op that exists so `xgettext` can see a msgid at a place the code cannot translate it.

### Translation happens at call time

`NAMES` in `lib/model.js` and `SERVICE_ISSUES` in `lib/policy.js` are module constants, evaluated at
import — before `enable()` has installed anything. Translating them where they are declared would
freeze English permanently, and would do so silently.

So the constants keep English msgids marked with `N_()`, and `_()` is applied where the value is
read: in `quotaName()` and in `serviceIssue()`.

Panel initials get a context, because a bare `S` is not translatable without one:

```js
const SHORTS = {session: () => p_('panel initial', 'S'), weekly_all: () => p_('panel initial', 'W')};
```

French wants `S` for *Session* and `H` for *Hebdomadaire*. `assignShort`'s derived initials for
model-scoped quotas (`Opus` → `O`) stay as they are — those come from proper nouns the API supplies.

### Durations become whole sentences

`relativeDuration` is replaced by `remainingLine(target, now)`, which returns the fragment including
its agreement:

| branch | msgid | plural on | French |
| --- | --- | --- | --- |
| past reset | `now` | — | `maintenant` |
| ≥ 1 day | `{d}d {h}h left` | days | `{d} j {h} h restants` |
| ≥ 1 hour | `{h}h {m}m left` | hours | `{h} h {m} restantes` |
| < 1 hour | `{m}m left` | minutes | `{m} min restante(s)` |

The three duration entries are `n_()` calls whose English singular and plural are identical; French
supplies two forms, and a language with more gets as many as its `Plural-Forms` header declares.
Hand-writing `count === 1 ? a : b` would be correct for French and wrong for Polish and Arabic.

`captionLine` reduces to `format('{remaining} · {time}', …)`.

Incidental fix: today `relativeDuration` returns `now` at the reset instant, which `captionLine`
renders as `now left`. Folding the branches removes the possibility.

### Numbers and times

`percentLine` moves to `Intl.NumberFormat(locale, {style: 'percent', maximumFractionDigits: 0})`,
which yields `21%` in English and `21 %` in French with the narrow no-break space French typography
requires. The panel uses the same function, so a French panel cell reads `S 21 %` and is a few pixels
wider; the responsive hide path in `_fitPanel` already exists for exactly this, and the French
screenshot is where that gets judged.

`absoluteTime` is unchanged. The `locale` it receives keeps coming from `LC_TIME`, deliberately
independent of the message language.

### Errors: French on screen, English in the log

`npm run logs` is a diagnostic surface, and an `attempts.jsonl` whose text varies by host locale is
worse than one with no text at all.

New `lib/errors.js`:

```js
export function describe(msgid, values = {}) {
    return {msgid, values, message: format(msgid, values)};
}

export function errorText(desc) {
    return format(_(desc.msgid), desc.values);
}
```

`describe()` interpolates without translating, so `message` is always English. `lib/usage.js` throws
`Object.assign(new Error(desc.message), {desc, …wire})`; `_fetchResult` carries `desc` alongside the
existing `error` string; `_applyResult` stores `this._error = result.desc`; `_renderMessage` renders
`errorText(this._error)`. The record written to `attempts.jsonl` is untouched.

Six error msgids, all on the usage path:

- `Cannot read ~/.claude/.credentials.json`
- `No Claude token in ~/.claude/.credentials.json`
- `Token expired, run Claude Code once` — French translates for meaning, not word for word:
  `Jeton expiré, relancez Claude Code`
- `Cannot reach api.anthropic.com`
- `Usage request failed (HTTP {status})`
- `Unexpected response from the usage endpoint`

`Rate limited` is thrown too, but the rate-limit path sets `_error` to `null` and renders its own
line, so the popup string is a separate msgid in `lib/format.js`.

### The issue row wraps

`_renderIssue` currently gains a wrap point only by inserting `\n` before the maintenance-end
fragment. A long label with no such fragment — `Performances dégradées` — has nowhere to break and
stretches the popup. Setting `line_wrap = true` on `_issueItem.label.clutter_text` fixes it.

The emoji stays outside the msgid. `⏳`, `🚧` and the rest compose with translated text without
grammar, and keeping them out of the catalog keeps a translator from losing the variation selector on
`⚠️` that `lib/policy.js` already documents.

### Catalogs on disk

```
po/claude-quota.pot          extracted, committed
po/fr.po                     translated, committed
locale/fr/LC_MESSAGES/claude-quota.mo    compiled, committed
```

`metadata.json` gains `"gettext-domain": "claude-quota"`, which names the `.mo` and is what the
`Extension` base class binds.

The `.mo` is a compiled artifact and it is committed anyway, because this repo's contract is that the
checkout *is* the shipped extension. Cloning into `~/.local/share/gnome-shell/extensions/` has to
produce a working French extension with no build step, and a `.mo` that exists only after `msgfmt`
breaks that.

`tools/i18n.sh` regenerates all three:

- `--extract` — `xgettext --language=JavaScript --keyword=_ --keyword=N_ --keyword=n_:1,2
  --keyword=p_:1c,2 --from-code=UTF-8` over `extension.js` and `lib/*.js`
- `--merge` — `msgmerge --update --backup=none po/fr.po po/claude-quota.pot`
- `--compile` — `msgfmt` into `locale/`
- `--check` — regenerate into a temporary directory and exit non-zero if anything differs from what
  is committed

`npm run i18n` runs extract, merge and compile. `--check` is the guard against a msgid added in code
and never extracted.

### Determinism in the harness

- `npm test` becomes `TZ=UTC LC_ALL=C node --test`.
- `tools/lib/devkit.sh` exports `LC_ALL=C` into the nested session by default, so tiles do not change
  shape on a French host.
- `tools/preview.sh` and `tools/e2e.sh` take `--locale=<tag>`, which sets `LANG` and `LC_ALL` for the
  nested session only. This is how the French rendering gets looked at.

No French assertion suite. Asserting 62 tiles in a second language proves that `msgfmt` works, which
is not in doubt; it costs a doubled e2e run on every future change and pins French wording into shell
fixtures where nobody will maintain it.

## Testing

| File | Proves |
| --- | --- |
| `test/i18n.test.js` | identity default; `setTranslator` routes `_`/`n_`/`p_`; `format` substitutes and leaves unknown placeholders alone; `resetTranslator` restores English |
| `test/po.test.js` | a small `.po` parser, then: every msgid in `claude-quota.pot` has a non-empty `msgstr` in `fr.po`, and every plural entry has as many forms as the `Plural-Forms` header declares |
| `test/errors.test.js` | `describe()` produces an English `message`; `errorText()` translates and interpolates |
| `test/format.test.js` | updated for `remainingLine`; new cases for `percentLine` under `fr-FR` (`21 %`) and the three duration branches under an installed French translator |
| `test/model.test.js` | `quotaName` and the short labels translate when a translator is installed |

`test/po.test.js` is the check that actually earns its place: it is the one that fails when a string
is added to the code and forgotten in the catalog.

Manual verification, since pixels are involved:

```
npm run preview -- --locale=fr --dark --scenario=critical --open
npm run e2e -- --locale=fr --group=state --dark-only
```

and the standing host-safety checks — `sha256sum ~/.config/dconf/user` and the length of
`gsettings get org.gnome.shell enabled-extensions` before and after, plus
`wc -l ~/.cache/claude-quota/attempts.jsonl` unchanged across the run.

## Risks

- **The `.mo` goes stale.** A msgid changes, `npm run i18n` is not run, and the shell silently falls
  back to English for that one string. `tools/i18n.sh --check` is the answer; it belongs in whatever
  runs before a commit.
- **Invisible characters in `po/fr.po`.** French wants U+202F before `%` and between number and unit.
  `Intl` supplies it for the percent; anywhere a translator types it by hand it is unreviewable in a
  diff. Keep hand-typed narrow spaces out of the catalog and let `Intl` produce them.
- **`Extension` translation binding is taken from documentation.** If GNOME 50 does not
  auto-initialise the domain, `enable()` calls `this.initTranslations()` explicitly. Confirmed
  against a running shell before anything else is built.
- **French panel cells are wider.** `S 21 %` against `S 21%`. Expected to be absorbed by the existing
  fitting logic; if it is not, the fix is a follow-up, not a special-case percent format.

## Later languages

The next catalogue is `msginit --locale=<tag>` plus a translated `.po` plus `npm run i18n`. Nothing
in `lib/` or `extension.js` should need to change; if it does, this design was wrong.

Translations after French are machine-authored and marked as such in the `.po` header, for a native
speaker to review later. Tier order when that happens: `de`, `es`, `pt_BR`, `it`, then `nl`, `pl`,
`tr`, `ja`, `ko`.
