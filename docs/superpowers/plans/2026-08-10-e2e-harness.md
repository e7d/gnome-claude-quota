# End-to-end harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `tools/e2e.sh`, a nested-shell suite that asserts what the extension renders and how it reacts, and that emits the screenshots `npm run a11y` scores — extracting the layer it shares with `tools/preview.sh` instead of duplicating it.

**Architecture:** `tools/preview.sh` splits into two libraries layered on the existing `tools/devkit.sh`: `tools/indicator.sh` drives the extension (scenarios, render, menus, pointer) and `tools/capture.sh` turns a rendered state into a PNG. `tools/assert.sh` adds assertions and negative controls with no GNOME dependency at all. `preview.sh` and `e2e.sh` are then thin drivers over those libraries.

**Tech Stack:** bash 5 (`set -euo pipefail`), `gdbus` against `org.gnome.Shell.Eval`, GJS evaluated inside a nested GNOME Shell 50, ImageMagick, `node --test` for the one library that can be unit-tested.

**Spec:** `docs/superpowers/specs/2026-08-10-e2e-harness-design.md`

## Global Constraints

- **No WHAT comments.** A comment is only acceptable when it documents a non-obvious WHY. The existing comments in `tools/preview.sh` that explain *why* (the `warp_pointer` note, the freeze note, the service-status note) move with their code unchanged. Do not write new ones to narrate a move.
- **No blank lines inside a function body.** Extract a sub-function instead.
- **Functions stay small** — 20 lines is the soft cap.
- **`shellcheck -x tools/*.sh` must pass.** That is the exact invocation CI uses (`.github/workflows/ci.yml:45`). Without `-x` it reports SC2034 on the `DEVKIT_*` vars, which is an artifact of the invocation, not a finding.
- **Every driver runs `set -euo pipefail`.** Assertion functions therefore **always return 0** and record their verdict in a counter; a non-zero return would abort the run at the first failure and lose the tally.
- **Host safety is non-negotiable.** Every dconf write stays inside the private `dbus-run-session` that `devkit.sh` sets up. Nested shells are killed by pid only — never match `gnome-shell` by name, the host session shares it.
- **`Eval` answers `(true, '<json>')` on success.** Anything else — including `(false, '')` — means not-ready and is never treated as data. Use the existing `is_true` and `unwrap`.
- **Bash tool syntax.** The user's login shell is fish; every command in this plan is bash and must be run as bash.
- **Commits are signed and carry the repo's trailer.** `git commit -S`, message ending in `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`. Work on branch `feat/e2e-harness`; never commit to `main`.
- **Never edit `extension.js` to stage a test failure.** Negative controls are runtime mutations only.
- **A running `.sh` must not be edited.** Bash re-reads a script by byte offset. Stop any watcher before editing `tools/*.sh`.

## File structure

| File | Responsibility | Task |
| --- | --- | --- |
| `tools/devkit.sh` | GNOME session lifecycle | unchanged |
| `tools/indicator.sh` | drive the extension: scenario table, state injection, menus, pointer, theme | 1 |
| `tools/capture.sh` | turn a rendered state into a PNG; settle sleeps; contact sheet | 2 |
| `tools/assert.sh` | assertion primitives, counters, `prove` | 3 |
| `tools/preview.sh` | human driver: flags plus the theme × scenario loop | 1, 2 |
| `tools/e2e.sh` | assertion driver: state matrix, then the interaction groups | 4–7 |
| `test/assert.test.js` | unit tests for `tools/assert.sh` | 3 |

## Parallelism

Task 3 touches no file that tasks 1 and 2 touch and needs no GNOME shell, so **task 3 can run in parallel with task 1**. Tasks 5, 6 and 7 each append one self-contained group function to `tools/e2e.sh` and can be **dispatched in parallel once task 4 has landed** — but they edit the same file, so either give each subagent its own worktree (`superpowers:using-git-worktrees`) or run them sequentially. Sequential is the safer default here: each group is 10–20 minutes and the merge cost of three subagents in one 200-line bash file exceeds the saving.

Everything else is strictly ordered: 1 → 2 → 4 → (5, 6, 7) → 8.

```javascript
import {test} from 'node:test';
import {execFileSync} from 'node:child_process';
import {fileURLToPath} from 'node:url';

const LIB = fileURLToPath(new URL('../tools/assert.sh', import.meta.url));

function run(script) {
    try {
        const stdout = execFileSync('bash', ['-c', `set -euo pipefail\n. "${LIB}"\n${script}`], {encoding: 'utf8'});
        return {status: 0, stdout};
    } catch (error) {
        return {status: error.status, stdout: error.stdout ?? ''};
    }
}

test('a passing assertion is counted and reported', () => {
    const {status, stdout} = run('assert_eq label one one\nassert_summary');
    assert.equal(status, 0);
    assert.match(stdout, /^ok label$/m);
    assert.match(stdout, /1 passed, 0 failed/);
});

test('a failing assertion reports both values and fails the summary', () => {
    const {status, stdout} = run('assert_eq label one two\nassert_summary');
    assert.equal(status, 1);
    assert.match(stdout, /FAIL label: expected 'one', got 'two'/);
    assert.match(stdout, /0 passed, 1 failed/);

    const {status, stdout} = run('assert_eq first one two\nassert_eq second three three\nassert_summary');

    assert.match(stdout, /^ok second$/m);
});

test('assert_not_empty rejects the empty string', () => {
    const {status, stdout} = run("assert_not_empty label ''\nassert_summary");
    assert.equal(status, 1);
    assert.match(stdout, /FAIL label: expected a value, got ''/);

test('prove accepts an assertion that fails under its break', () => {
    const script = `

        check() { [ "$BROKEN" -eq 0 ] && assert_eq check ok ok || assert_eq check ok broken; }
        prove check 'BROKEN=1' 'BROKEN=0' check

    assert.equal(status, 0);
    assert.match(stdout, /^prove check$/m);

test('prove leaves the tally untouched', () => {
    const script = `
        BROKEN=0
        check() { [ "$BROKEN" -eq 0 ] && assert_eq check ok ok || assert_eq check ok broken; }
```

```bash
# shellcheck shell=bash

ASSERT_PASSED=0
ASSERT_FAILED=0

assert_pass() {
    ASSERT_PASSED=$((ASSERT_PASSED + 1))
    echo "ok $1"
}

assert_reject() {
    ASSERT_FAILED=$((ASSERT_FAILED + 1))
    echo "FAIL $1: $2"
}

assert_eq() {
    if [ "$2" = "$3" ]; then
        assert_pass "$1"
    else
        assert_reject "$1" "expected '$2', got '$3'"
    fi
    return 0
}

assert_ne() {
    if [ "$2" != "$3" ]; then
        assert_pass "$1"
    else
        assert_reject "$1" "expected anything but '$2'"
    fi
    return 0
}

assert_not_empty() {
    if [ -n "$2" ]; then
        assert_pass "$1"
    else
        assert_reject "$1" "expected a value, got ''"
    fi
    return 0
}

assert_summary() {
    echo "$ASSERT_PASSED passed, $ASSERT_FAILED failed"
    [ "$ASSERT_FAILED" -eq 0 ]
}

assert_abort() {
    echo "control $1: $2" >&2
    exit 1
}

# A verdict read from output would depend on formatting; the counter is the fact.
assert_quiet() {
    local passed="$ASSERT_PASSED" failed="$ASSERT_FAILED" verdict=0
    "$1" >/dev/null
    [ "$ASSERT_FAILED" -eq "$failed" ] || verdict=1
    ASSERT_PASSED="$passed"
    ASSERT_FAILED="$failed"
    return "$verdict"
}

prove() {
    local label="$1" break_cmd="$2" restore_cmd="$3" fn="$4"
    assert_quiet "$fn" || assert_abort "$label" 'failed before the break was applied'
    eval "$break_cmd"
    assert_quiet "$fn" && { eval "$restore_cmd"; assert_abort "$label" 'still passed with the break applied'; }
    eval "$restore_cmd"
    assert_quiet "$fn" || assert_abort "$label" 'did not recover after the restore'
    echo "prove $label"
}
```

```bash
#!/usr/bin/env bash
set -euo pipefail

DEVKIT_NAME='e2e'
DEVKIT_SETUP='gsettings set org.gnome.desktop.interface font-name "Cantarell 11"'
DEVKIT_HEADLESS=1
# shellcheck source=tools/devkit.sh
. "$(dirname "${BASH_SOURCE[0]}")/devkit.sh"
# shellcheck source=tools/indicator.sh
. "$(dirname "${BASH_SOURCE[0]}")/indicator.sh"
# shellcheck source=tools/capture.sh
. "$(dirname "${BASH_SOURCE[0]}")/capture.sh"
# shellcheck source=tools/assert.sh
. "$(dirname "${BASH_SOURCE[0]}")/assert.sh"

# GROUPS is a bash built-in holding the user's gids, and assignments to it are ignored.
ALL_GROUPS=(state hover refresh lifecycle)
RUN_GROUPS=("${ALL_GROUPS[@]}")
THEMES=(dark light)
SHOOT=(normal warning critical model-scoped error service-major over-pace rate-limited no-data)
PICKED_GROUPS=()

usage() {
    cat <<USAGE
Usage: tools/e2e.sh [options]

Asserts what the extension renders and how it reacts, in a throwaway nested GNOME
shell, and shoots the subset of states npm run a11y scores.

Options:
  --headless           Run with no window, driven over D-Bus (default)
  --windowed           Show the session in a Mutter devkit window
  --dark-only          Assert the dark theme only
  --light-only         Assert the light theme only
  --scenario=<name>    Assert one scenario; repeat the flag for several
  --group=<name>       Run one group; repeat the flag for several
  -h, --help           Show this message

Screenshots belong to the state group, so a run that excludes it leaves
preview/ alone and npm run a11y would score whatever was already there.

Groups:
  ${ALL_GROUPS[*]}

Scenarios:
  ${SCENARIOS[*]}

Needs magick, and gnome-shell with this checkout symlinked at
$INSTALLED
USAGE
}

for arg in "$@"; do
    devkit_flag "$arg" && continue
    case "$arg" in
        --dark-only) THEMES=(dark) ;;
        --light-only) THEMES=(light) ;;
        --scenario=*) PICKED+=("${arg#*=}") ;;
        --group=*) PICKED_GROUPS+=("${arg#*=}") ;;
        -h|--help) usage; exit 0 ;;
        *) die "unknown option $arg" ;;
    esac
done

select_groups() {
    local want known found
    [ "${#PICKED_GROUPS[@]}" -gt 0 ] || return 0
    for want in "${PICKED_GROUPS[@]}"; do
        found=''
        for known in "${ALL_GROUPS[@]}"; do
            [ "$known" = "$want" ] && found=1 && break
        done
        [ -n "$found" ] || die "unknown group '$want'; known: ${ALL_GROUPS[*]}"
    done
    RUN_GROUPS=("${PICKED_GROUPS[@]}")
}

runs_group() {
    local name
    for name in "${RUN_GROUPS[@]}"; do
        [ "$name" = "$1" ] && return 0
    done
    return 1
}

probe() {
    shell_eval "JSON.stringify($1)" | unwrap
}

main() {
    require_install
    require_commands magick
    select_scenarios
    select_groups
    isolate_dconf
    start_shell
    wait_for_indicator
    hide_overview
    freeze
    runs_group state && group_state
    runs_group hover && group_hover
    runs_group refresh && group_refresh
    runs_group lifecycle && group_lifecycle
    assert_summary
}

main
```

`probe` is the one primitive every group uses: it evaluates an expression, JSON-encodes it in the shell so a string with spaces survives, and `unwrap` strips the `(true, '…')` envelope and the quotes. An `Eval` that fails answers `(false, '')`, which `unwrap` turns into the empty string — indistinguishable from a legitimately empty value, which is why every assertion below tests for a *specific* expected value and never for mere non-emptiness of a probe result.

```bash
    .filter(c => /cq-panel-quota/.test(c.get_style_class_name() ?? ''))

}

        "$(probe "$IND._blocks.every((b, n) => ($PANEL_QUOTAS)[n].endsWith(b._percent.text))")"

    assert_no_placeholders "$1"

```

`assert_panel_matches` compares the panel against the blocks rather than re-deriving `percentLine` in bash. A panel label reads `S 7%` and a block's percent reads `7%`, so `endsWith` is the relationship, and any rule change in `lib/format.js` keeps both sides honest without touching this file.

It indexes `PANEL_QUOTAS`, not `PANEL_LABELS`: `_renderPanel` interleaves separator labels whose text is `·`, so a positional index over every non-empty label misaligns after the first block. `PANEL_LABELS` stays as the input to `assert_no_placeholders`, where the separators, the service emoji and the `-`/`…` empty-state label are extra coverage rather than noise.

## What execution corrected

Every task landed, and ten of the plan's stated facts turned out to be wrong about the real shell. `tools/e2e.sh` is the truth; this section records the mechanism behind each correction, because most of them are traps that will recur.

| # | The plan said | What is actually true |
| --- | --- | --- |
| 4 | `GROUPS=("${ALL_GROUPS[@]}")` | `GROUPS` is a bash built-in holding the user's gids and **assignments to it are ignored**, so the dispatch compared names against numbers, ran no group, and exited 0 reporting `0 passed, 0 failed`. Renamed `RUN_GROUPS` |
| 4 | index `PANEL_LABELS` by block position | `_renderPanel` interleaves `·` separator labels, so the index misaligns after block 0 and the assertion could never pass. Select by the `cq-panel-quota` class |
| 5 | hovered shape is `'true\|hover\|true'` | Real shape is `true\|first-child last-child hover\|true`, and `probe` returns it gdbus-escaped, so no bash literal could match. Capture `quickSettings`' shape live and compare |
| 5 | compare the two buttons as they are | `PanelMenu.Button` adds `active` while its menu is open, so the resting comparison never matches with the popup up. Compare both in the same menu state |
| 5 | point at `_body` and `_message` under `service-major` | `_renderMessage` blanks the error whenever a service issue exists, so `_message` and `_issueItem` are **mutually exclusive**. An unmapped actor's `get_transformed_position()` returns NaN, which warps the pointer to `INT_MIN`. Display rows render under `error` |
| 5 | a pointer move is inert | **The session's first pointer motion closes an open menu when it lands inside it.** This produced a false green: a control passed while the menu was shut. `reopen_menu` moves once with the menu deliberately closed |
| 6 | `_refreshButton.emit('clicked')` | `St.Button::clicked` carries the button number — `Signal 'clicked' on StButton requires 1 args got 0`. `shell_eval` discards stderr and gdbus exits 0, so the click **silently did nothing**. `emit('clicked', 1)` |
| 6 | restore `_refresh` only | `_fetchCycle` must be deleted too, or the next group inherits an indicator whose fetch never settles |
| 7 | `_init`'s `_refresh()` schedules `_timerId` | `_refresh` is async and schedules only in `_applyResult`, **after the fetch settles**. Measured `_timerId=null, _refreshing=true` on the first read, a real id ~0.5s later. Poll for it |
| 7 | `sleep 1` after `disableExtension` | It only writes settings; teardown runs later from the awaited handler. Poll the panel instead |

Two properties of the harness are worth carrying forward. **A mutating `shell_eval` can silently no-op**, since stderr is discarded and gdbus exits 0 regardless — which is why state is read back rather than assumed. And **the negative controls caught most of the above**: a break that fails to apply leaves the assertion passing, which `prove` reports as `still passed with the break applied`.

Measured on completion: **206 assertions, 0 failures, ten controls, 1m59s** on the host; 111 unit tests; 19 files in `preview/`; host dconf digest unchanged across every run.
